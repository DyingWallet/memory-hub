# MEMORY-WEIGHTING.md — 记忆加权模型

> 状态：**模型定稿，未实现**（2026-10-28 修订：去掉任务层，只留记忆层）。
> 一句话：检索分数不该只看「相关不相关」，还要看**这条该记多久、熟不熟、话有没有说完**。

---

## 一、这不是任务管理系统

这条要先写死，否则会越设计越像 TODO：

| 这份文档管 | 不管 |
|---|---|
| 一条相关的记忆，有多容易排到前面 | 有什么事要做、先做哪件 |
| 这条该记多久 | 什么时候到 deadline |
| 这段话说完了没有 | 完成了百分之几 |

**判据**：如果一条记忆完全没有「事要做」的含义，它也应该被这套模型照顾。

「他喜欢喝咖啡」没有截止日期、没有完成度、没有优先级——但它该记得住。**如果模型对这类记忆失效，那就不是记忆模型，是任务模型。**

---

## 二、三个量

| 量 | 范围 | 来源 | 变不变 | 管什么 |
|---|---|---|---|---|
| `importance` | 0–3 | 整理会话写入时标注 | **不变** | 这条该记多久 |
| `strength` | ≥0 | 痕迹衰减（见 §3.1） | 随时间变 | 熟不熟 |
| `openLoop` | 0 / 1 | 整理会话判定 | 直到收尾 | 这段话说完了没 |

`importance` 的四档不是线性的：**0/1/2 是「沉得慢」，3 是「几乎不沉」**（50 年半衰期，见 §3.1）。所以标 3 要非常克制——它不是「很重要」，是「忘了会出事」。

三个字段，两个乘数。就这样。

---

## 三、合成

### 3.1 强度

```js
const TAU = 14;                                   // 天
// importance = 3 走「几乎不衰减」档：50 年半衰期，而不是线性外推的 56 天
const baseTau = importance >= 3 ? 18250 : TAU * (1 + importance);
// 用得多 → 沉得慢。对数放大，边际递减：n=10 约 2.2 倍，n=100 约 3.3 倍
const tau = baseTau * (1 + 0.5 * Math.log(1 + recall_count));

strength(now) =
    exp(-(now - createdAt) / tau)                 // ① 写下来那一刻的痕迹
  + (closedAt ? exp(-(now - closedAt) / tau) : 0) // ② 收尾那一下（见 §4）
```

**两条痕迹，不是三条。** 早期版本用「每次召回叠一道痕迹」（spacing effect 的原样实现），但它需要每次召回的时间戳；只用 `recall_count` 近似会系统性高估——把一年前衰减掉的痕迹当成昨天刚发生的。

改成**放大 `tau`** 之后，表达的语义变成「用得多 → 沉得慢」，而不是「用得多 → 强度高」。代价是失去了「密集使用 vs 稀疏使用」的区分，收益是不需要 `touches` 表、没有分布偏差、`log` 天然封顶。

| importance | tau | 1 年后还剩 | 大约多久沉到 1/e |
|---|---|---|---|
| 0 | 14 天 | 0% | 两周 |
| 1 | 28 天 | 0% | 一个月 |
| 2 | 42 天 | 0.02% | 六周 |
| 3 | **18250 天** | **98%** | 五十年 |

**第 3 档是个断崖，不是线性外推。** 它不是「沉得慢」，是「几乎不沉」——所以它的调节旋钮不在 `tau` 上，在 §9.1 的标注判据上：标 3 太难，它就会太多。

`importance = 3` 的实际衰减曲线：

| 时间 | 还剩 |
|---|---|
| 1 年 | 98.0% |
| 5 年 | 90.5% |
| 10 年 | 81.9% |
| 20 年 | 67.0% |
| 50 年 | 36.8% |

**代价**：这一档的东西过时了也不会沉（比如约定完成之后）。可接受，因为相关性门槛还在——不相关它不会出现。

**重要性不直接加分，它只改变衰减速度。**「重要」的语义是「记得久」，不是「排得前」。

### 3.2 检索分

```js
const BETA  = 0.30;   // 强度微调
const K     = 3;      // tanh 归一化尺度
const DELTA = 0.30;   // 未闭合加成

score = baseScore
      * (1 + BETA  * Math.tanh(strength / K))
      * (1 + DELTA * openLoop);
```

两个乘数，各管一件事：

- `strength` → 熟不熟（沉底了就弱）
- `openLoop` → 话说完了没（没说完的更容易被想起）

`baseScore` 是门槛：**乘数不能把不相关的事拽上来**。相关性低于下限的命中，两个乘数一律不生效。

`tanh` 是防止强度无限增长——用了 3 次和 30 次，对排序的影响差别很小，避免赢家通吃。

## 四、openLoop 不是「任务」，是「话头」

这是最容易滑向 TODO 的地方，所以定义要精确：

| | openLoop（这份文档） | 任务（不在这份文档里） |
|---|---|---|
| 是什么 | 一段对话没闭合 | 一件要做的事 |
| 例子 | 「那个 bug 很怪」然后没下文了 | 「周三前把文档改完」 |
| 有没有截止 | 没有 | 有 |
| 做什么 | 相关时更容易被想起 | 催、排优先级、追踪进度 |
| 怎么结束 | 对话里接上了 | 做完了 |

**触发方式只有「提起」，没有「催办」。** `openLoop = 1` 的唯一效果是：当这条记忆被相关查询命中时，它更容易排在前面。

它不会让谁在没人叫的时候说话——那不在这个模型的范围里。

**收尾**：`openLoop` 关闭时会在 `strength` 里留下最后一次痕迹（§3.1 的第 ③ 项）。所以「说完的事」比「一直悬着的事」留下的印象略深——这符合直觉，但差别不大，只是多一次使用痕迹的量级。

---

## 五、沉底不是遗忘

这份模型**不删除任何数据**。`facts/*.jsonl` 是 append-only，衰减只影响排序权重。

| 不说 | 说 |
|---|---|
| 遗忘、忘掉、没了 | **沉底**、退到背景、不再主动浮现 |
| 权重归零 | 沉底（强相关时仍然召得回） |
| 删掉了 | （只有显式 `forget` 才删） |

区别很实在：一条沉底的记忆，你哪天提一个高度相关的词，它照样排得上来。它只是不再「随手就浮上来」。

> 所以衰减是**注意力分配**，不是**数据生命周期**。

## 六、存储与可重建

`reindex --force` 之后所有数值必须与之前一致。这条约束决定了哪些能存、哪些必须算。

| 数据 | 存哪 | 可变 | 重建方式 |
|---|---|---|---|
| 原始事实 | `facts/*.jsonl` | 否 | — |
| `importance` | jsonl 元数据字段 | 否 | 直接读 |
| 使用日志 | `touches(id, at, kind)` 表 | **只追加** | 原始数据 |
| `openLoop` / `closedAt` | SQLite `memories` 表 | 是 | 从日志重放 |
| **`strength`** | **不存** | — | **每次按 §3.1 现算** |

关键：**`strength` 永远不落盘**。只要 `importance`、`touches`、`openLoop` 在库里，就能确定性重算。

## 七、可观测性

三个量乘在一起，出错时看不出是哪个错。所以检索接口必须能 dump 分量：

```
GET /v1/search?q=...&explain=1
→ [{ id, title, baseScore, strength, importance, uses, lastUsedAt,
     openLoop, finalScore }]
```

没有这个，「为什么这条排第一」永远查不清，调参就是盲的。

## 八、落地顺序

一次设计，两个 PR。

### PR 1 — 地基（只做记忆层）

- Schema：`memories` 加 `importance`、`open_loop`、`closed_at`
- 整理会话：写入时标注 `importance`（标准见 §9.1）
- 检索：接上 `strength` 这一个乘数（`openLoop` 恒为 0）
- `?explain=1`
- **可回滚**：纯排序改动，不写任何新数据

上线后能直接看到「重要性 → 衰减速度」对不对。

### PR 2 — 动态

- `touches` 表 + 桥接注入后的 `POST /v1/touch`（fire-and-forget，失败只记日志）
- 整理会话判定 `open_loop`（话没说完、问了没答、答应了没提）
- 接上 `openLoop` 乘数

## 九、参数与失败模式

### 9.1 importance 的标注标准

这是整套里最容易做烂的一环。标注含糊 → 全是 2 → 等于没有。

| 值 | 判据 | 例子 |
|---|---|---|
| 0 | 说完就过，明天不会想起 | 「今天下雨了」「刚吃完饭」 |
| 1 | 有点信息量，但不需要记住 | 「那个剧更新了」 |
| 2 | 偏好、决定、别人告诉我的事 | 「他不吃辣」「下周要交文档」 |
| 3 | **忘了会出事**：身份、关系、健康、约定 | 「他爸去年做过手术」「我们约定的那件事」 |

**3 这一档的判据是「忘了会不会造成伤害」，不是「重不重要」。** 因为它是 50 年半衰期，标错了一个就永远沉不下去：
- 「那个项目很重要」→ **不是 3**。忘了顶多是不记得，不会伤到关系。给 2。
- 「他不能接受别人碰他的电脑」→ **是 3**。忘了会出事。

标注 prompt 用二选一问句，别让模型自由发挥：

> **这件事如果三个月后忘了，会不会有问题？** 答「会」才给 2 以上。
>
> 再问一句：**忘掉它会不会伤到他？** 答「会」才是 3，否则最多 2。

注意 `importance = 2` 里**不包含「优先级」**——「下周要交文档」是 2，因为它是个要紧的事实；但这份文档不关心「要不要催」。

### 9.2 失败模式

跑三个月后如果出现这两种，正好是对称的：

| 现象 | 说明 | 拧哪个 |
|---|---|---|
| 只记得天天聊的事，要紧但冷门的事沉了 | 强度压过分量 | `BETA` 调小，或 importance 标注标准收紧 |
| 老提早就该翻篇的事 | 衰减太慢 | `TAU` 调小，或 `DELTA` 调小 |

**一次只动一个参数**，否则分不清是哪个拧过头了。

## 十、边界：这套东西不做什么

1. **不管任务的推进。** 没有 deadline、没有优先级、没有完成度、没有催办。
2. **不做主动驱动。** 只影响「被检索时的排序」，不会让她在没人叫的时候主动说话。
3. **不用数值模拟内在状态。** 没有 `pressure`、没有「渴望值」、没有「焦虑」。所有量记录的都是**发生过的事实**（用了几次、话说没说完）。
4. **不删除数据。** 衰减只降权。
5. **不改相关性检索本身。** `baseScore` 的门槛高于一切乘数。

## 附：一页速查

```
importance  0-3      写入时标，永不变     → 决定 tau（0/1/2: 14×(1+imp) 天；3: 18250 天）
strength    ≥0       痕迹衰减，每次算      → ×(1 + 0.30·tanh(strength/3))
openLoop    0/1      话没说完              → ×(1 + 0.30·openLoop)
closedAt    时间/空   收尾时写              → 给 strength 加一条痕迹

score = baseScore × 强度 × 未闭合
       ↑ 门槛：不相关的一律不动

不做的：deadline / urgency / readiness / 优先级 / 催办
```
