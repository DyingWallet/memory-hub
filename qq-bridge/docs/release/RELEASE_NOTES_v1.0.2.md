# qq-bridge-enhanced v1.0.2

在 v1.0.1 的基础上的小版本：**换 SnowLuma 目录（例如升级到 SnowLuma 2.x）时，新目录缺数据会先提醒迁移**，并补充 SnowLuma WebUI 登录相关的常见问题；同时修复 Windows 实机部署 v1.0.1 时发现的问题；**控制台可以选择 DSH 的提供方 / 模型 / 思考强度**，保存即生效。
支持系统不变：**Windows、macOS、Linux**。逐条改动见 [CHANGELOG.md](../../CHANGELOG.md)。

## 新功能与改进

- **控制台选择 DSH 模型**（GitHub issue #1）：运行总览「DSH 模型与思考强度」改成提供方、模型、思考强度三个联动下拉，外加「看图能力」。
  选项全部来自 DSH 的模型目录，在 DSH 里配好的其它提供方桥接也能用；保存后对已有会话的下一条消息生效，不用重启桥接。默认仍是 `deepseek-flash` + `max`。
  - 服务端按目录硬校验：不在目录里的提供方 / 模型、该模型不支持的档位都会拒绝；目录读不到时不保存，页面标注「目录不可用」；
  - 档位以模型自己公布的为准，**`off`（关闭思考）也能选**，选它时提示工具调用和回复质量可能变差；没有思考档位的模型强度下拉置灰；
  - **不能看图的模型自动把图片改成文字**：DSH 目录不说明模型能不能看图，所以默认只有核实过的 `deepseek-flash` 收图，其它模型的 QQ 图片、表情改成「[图片1：当前模型 … 不能看图，已省略]」，避免整条消息被拒；确认能看图可以手动设为「能看图」；
  - **换到第三方提供方时提示隐私**：QQ 聊天内容会发给它处理，第一次保存前再确认一次；
  - 价格表只覆盖 DeepSeek 自家价目，其它模型标「价格未覆盖」，花费按 Flash 估算并标「估算」；
  - 只有控制台能改：QQ 里的 AI 和私聊管理通道都改不了模型。和以前的思考强度一样，切换会同时写入 DSH 的全局默认。
- **换 SnowLuma 目录前提醒迁移数据**：在控制中心换到新的 SnowLuma 目录时，如果新目录里既没有账号配置（`config/onebot_<QQ号>.json`）也没有 WebUI 密码（`config/webui.json`），而旧目录有，**先不切换**，弹出提醒——
  直接换过去 SnowLuma 会当成全新安装：生成新的随机 WebUI 密码（浏览器里保存的旧密码失效）、要重新扫码登录、重新开启 OneBot WebSocket，接口平台也找不到原来的账号。
  - 点「**去迁移（推荐）**」：打开更新助手并填好新目录；停止 SnowLuma 后点「迁移数据并切换」，旧目录的 `config/`（含 WebUI 密码）、`data/` 会先备份再复制过去，旧目录原样保留；
  - 不迁移的话要再确认一次「仍然切换」才会切换；
  - 第一次选目录、新旧目录相同、旧目录本来就没有数据、新目录已经迁移过时不提醒。
- **常见问题（部署文档「常见错误」）**：
  - 升级后旧密码登录不了：多半是新目录没带上旧的 `config/`，或旧版从没改过初始密码（每次启动都会重新生成）——用更新助手迁移，临时密码登录后改成正式密码；
  - 输对密码也登不进、提示「登录尝试过多」：SnowLuma 同一地址 5 次输错锁 15 分钟，锁定期间正确密码也会被拒；重启 SnowLuma 或等 15 分钟即解除，`localhost` 与 `127.0.0.1` 分开计数；
  - 改密码提示「新密码不得与旧密码相同」：说明填的「当前密码」就是现在存着的密码，直接用它登录即可。

（核对结论：SnowLuma 1.14.22 与 2.0.3 的 WebUI 密码存储格式、密码规则、读取逻辑完全相同，升级本身不会让密码失效。）

- **黑话研究：未确认的 AI 推测显示在控制台**：DSH 研究后没能确认的词，以前只在日志里留一句推测，现在存进词条，
  「候选词-待研究」的卡片上显示一行灰色斜体「AI 推测（未确认，时间）：……」，重启也不丢。
  - 点「**采用为含义**」：把推测填进编辑框里空着的栏位，核对修改后点「保存修改」——词条移到「候选词-已研究」，仍是候选，确认还要你再点；
  - 推测**不是含义**：不算「已研究」、不能凭它确认、**不会注入给 AI**，也不会出现在 AI 能读到的任何数据里；
  - 研究确认、或你填了含义 / 确认之后，推测自动清空；再研究仍未确认时更新为最新一次的推测。

## 修复（来自 Windows 实机部署 v1.0.1 的反馈）

- **Release ZIP 的中文文件名在 Windows 上乱码、解压失败**（`roles/小鲸鱼.md`、`assets/deepseek娘.png` 等）：v1.0.0、v1.0.1 的包是用 macOS 自带的 zip 打的，没有「文件名是 UTF-8」标志。
  现在发布脚本自己生成 ZIP，每个文件都带这个标志，`.command` / `.sh` 保留可执行位；Windows「全部解压」、macOS 双击、Linux `unzip` 都正常。
- **重置会话后提示「该会话已有一个等待中的 qq_wait_for_messages」**：控制台 / 控制中心的「重置会话」、QQ 里的 `/reset`、二代仿真全量重置都没清等待租约，新会话最长要等 15 分钟。现在重置时一并清掉。
- **黑话研究日志**：以前「已更新 N 条」把未确认（实际没写库）的也算进去。现在分别显示「写入 / 解析 / 未确认」条数，未确认的附上 AI 的推测（仍然不写库）。
- **接口平台里默认的 SnowLuma 实例标红**（从 v0.4.x 升级后第一次启动平台）：控制中心知道 SnowLuma 目录时自动给它补上；用户自己配过令牌的实例不动。
- **两个测试在 Windows 上失败**：路径写法改为 `fileURLToPath` / `path.posix`，并加回归测试防止再出现。
- **两个测试在 macOS 上失败**（`test-audit-bridge`、`test-voice`）：macOS 默认临时目录是软链接，语音库路径断言前缀对不上；测试夹具改为先取 realpath（只改测试）。
- **部署文档**：第 13 节新增「换了程序目录之后」必做清单；常见错误补充：工作目录不存在、等待租约残留、双击 .vbs 没反应、解压中文文件名乱码。

## 从 v1.0.1 升级

1. 退出控制中心；备份 `config.json`、`state/`、`interface-platform/state/`。
2. 解压到新目录，把上面三样复制过去（以及 `audio/`、自定义 `roles/*.md`，如有）。
3. `npm ci` → `npm run test:audit`；macOS 删掉旧的「QQ Bridge 控制中心.app」后双击一次 `control-center.command`；Linux 运行 `npm run linux-service -- --enable`。
4. 启动控制中心。没有数据格式变化，不需要重跑 `setup-dsh.mjs`。
5. 如果换了程序目录，按部署文档第 13 节「换了程序目录之后」的清单检查一遍（先在控制台重置会话，再删旧目录）。
